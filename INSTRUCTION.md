# Инструкция по использованию бота

Телеграм-бот для **самопроверки** персональных данных на предмет утечек.

Бот проверяет только данные **самого пользователя** и только после того,
как тот подтвердил, что контакт принадлежит ему. Поиск информации о третьих
лицах не предусмотрен.

---

## 1. Что умеет бот

| Проверка  | Как подтверждается владение | Источник |
|-----------|-----------------------------|----------|
| **Email** | код, отправленный на этот адрес | Have I Been Pwned API |
| **Телефон** | кнопка Telegram «Поделиться контактом» | открытые базы утечек¹ |
| **Пароль** | подтверждение не нужно — проверяется анонимно | Pwned Passwords API (k-анонимность) |
| **Цифровой след другого человека** | тот сам нажимает «Разрешаю» в ответ на запрос | скан соцсетей по его @username |

¹ Проверка телефона по умолчанию — заглушка (`check_phone_breach` возвращает
пустой результат). Подключите собственный источник, если он у вас есть.

Пароль **никогда не передаётся целиком**: бот считает SHA-1 локально и
отправляет сервису только первые 5 символов хэша (метод k-анонимности).

## 3. Настройка

### 3.1. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

| Переменная | Назначение | Обязательна |
|------------|-----------|-------------|
| `BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) | да |
| `HIBP_API_KEY` | ключ [Have I Been Pwned](https://haveibeenpwned.com/API/Key) | для проверки email |
| `SMTP_HOST`, `SMTP_PORT` | SMTP-сервер для отправки кодов | для проверки email |
| `SMTP_USER`, `SMTP_PASSWORD` | логин/пароль SMTP | если сервер требует авторизацию |
| `SMTP_FROM` | адрес отправителя | для проверки email |
| `SMTP_USE_TLS` | `true` — STARTTLS (порт 587), `false` — SSL (порт 465) | нет (по умолчанию `true`) |

Без настроенного SMTP проверка email будет корректно отключена с понятным
сообщением — бот при этом не падает.

### 3.2. Файл `config.py`

Бот читает настройки через объект `config`. Файл `config.py` не хранится в
репозитории (он в `.gitignore`). Пример содержимого:

```python
import os
from dotenv import load_dotenv

load_dotenv()

class Config:
    BOT_TOKEN = os.getenv("BOT_TOKEN")
    HIBP_API_KEY = os.getenv("HIBP_API_KEY")

    SMTP_HOST = os.getenv("SMTP_HOST")
    SMTP_PORT = int(os.getenv("SMTP_PORT", 587))
    SMTP_USER = os.getenv("SMTP_USER")
    SMTP_PASSWORD = os.getenv("SMTP_PASSWORD")
    SMTP_FROM = os.getenv("SMTP_FROM")
    SMTP_USE_TLS = os.getenv("SMTP_USE_TLS", "true").lower() == "true"

config = Config()
```

## 6. Сценарии использования

### Проверка email
1. `/check` → «📧 Проверить мой email».
2. Введите адрес. На него придёт 6-значный код (действует 10 минут).
3. Введите код в чат. После подтверждения бот проверит адрес по HIBP и
   покажет отчёт со списком утечек, **оценкой критичности** и разбором,
   какие именно категории данных утекли (см. раздел ниже).

Код можно запросить не чаще раза в минуту; на ввод даётся 5 попыток.

### Проверка телефона
1. `/check` → «📱 Проверить мой телефон».
2. Нажмите кнопку «Поделиться моим контактом».
3. Бот принимает только **ваш собственный** контакт (сверяет `user_id`);
   чужой пересланный контакт будет отклонён.

### Проверка пароля
1. `/check` → «🔑 Проверить пароль».
2. Отправьте пароль. Сообщение сразу удаляется из чата.
3. Бот сообщит, сколько раз этот пароль встречался в утечках.

### Проверка чужого цифрового следа — только с согласия человека
Отдельный сценарий для случая, когда нужно проверить публичный след другого
человека (его аккаунты в соцсетях по @username). Проверка запускается
**только после явного согласия самого проверяемого**:

1. Проверяемый должен сам запустить бота (нажать /start) — иначе Telegram
   не позволит боту написать ему, и запрос доставить некуда.
2. Оператор: `/request @username`.
3. Боту приходит запрос этому человеку с кнопками «✅ Разрешаю» / «🚫 Нет».
4. Если он нажал «Разрешаю» — бот сканирует **его собственный** публичный
   след и отправляет отчёт оператору. Если «Нет» — ничего не выполняется.

Гарантии:
- подтвердить согласие может только сам субъект (сверяется `user_id`);
- запрос одноразовый и живёт 15 минут;
- повторный запрос тому же человеку — не чаще раза в 5 минут;
- собирается **только** собственный след субъекта; данные третьих лиц
  (например, участники общих чатов) не собираются принципиально.

> Важно: это техническое согласие субъекта. Оно не заменяет вашей
> ответственности за законность проверки — убедитесь, что у вас есть на неё
> право (письменное разрешение, служебное основание и т. п.). Скан соцсетей
> выполняется best-effort: часть площадок защищена от автопроверок, поэтому
> возможны пропуски.

## 6.1. Анализ утечек: критичность и сопоставление

Чтобы пользователь понимал не только «утекло/не утекло», но и **что именно**
утекло и **насколько это опасно**, в боте есть офлайн-движок анализа
(`modules/correlation.py`). Он работает только с данными самого субъекта и не
ходит в сеть.

**Оценка критичности** (`assess_breach_criticality`). По категориям данных из
ответа HIBP (`DataClasses`) определяется уровень: 🟢 низкая → 🟡 средняя →
🟠 высокая → 🔴 критическая. Логика по уровням:

| Уровень | Примеры категорий |
|---------|-------------------|
| 🔴 критическая | пароли, банковские/карточные данные, security-вопросы |
| 🟠 высокая | телефон, адрес, дата рождения, документы, геолокация, переписка |
| 🟡 средняя | email, username, имя, IP, работодатель |
| 🟢 низкая | активность на сайте, устройство, часовой пояс, аватар |

Итоговый уровень — наивысший среди найденных категорий. К отчёту прилагаются
рекомендации.

**Сопоставление с профилем** (`match_profile`). Помогает понять, относится ли
найденная/утёкшая запись к самому пользователю. Сравниваются только те поля,
что есть у обоих: ФИО (по множеству слов, порядок не важен), username
(нечёткое сравнение), город, год рождения (±1 год), интересы (коэффициент
Жаккара). Возвращает уверенность 0..1 и список совпавших полей.

**Похожие ники** (`find_similar_handles`). По нормализованному нику ищет
похожие варианты из списка (например, чтобы сопоставить разные алиасы одного
человека в его же утечках). Порог похожести настраивается.

Все функции чистые (без сети и состояния) и покрыты тестами
`tests/test_correlation.py`.

## 7. Тесты

```bash
pip install pytest
pytest -q
```

Покрыто:
- `tests/test_verification.py` — генерация кодов, срок жизни, лимит попыток,
  антифлуд, независимость email/телефона;
- `tests/test_validators.py` — определение типа ввода, проверка
  email/телефона/username, нормализация номера;
- `tests/test_consent.py` — согласия, реестр пользователей, лимиты;
- `tests/test_correlation.py` — критичность, сопоставление профиля,
  похожие ники.

## 8. Структура проекта

```
bot.py                   # точка входа, запуск поллинга
handlers/
  start.py               # /start, /help
  search.py              # /check — самопроверка (email / телефон / пароль)
  consent.py             # /request — проверка следа по согласию субъекта
  callback.py            # резерв под callback-обработчики
modules/
  breach_check.py        # HIBP (email) и Pwned Passwords (пароль)
  social_search.py       # скан публичного следа (по согласию субъекта)
  correlation.py         # критичность утечек + сопоставление с профилем субъекта
  telegram_api.py        # Telethon-клиент (в текущих флоу не задействован)
utils/
  validators.py          # проверка/нормализация ввода
  verification.py        # коды подтверждения владения (email/телефон)
  consent.py             # согласия на проверку следа + реестр пользователей
  mailer.py              # отправка кода на email по SMTP
  formatters.py          # сборка отчётов
tests/                   # автотесты (валидаторы, коды, согласия)
```

## 9. Ограничения и правовая рамка

- Бот предназначен **только для проверки собственных данных пользователя**.
  Владение email и телефоном подтверждается технически, поэтому проверить
  чужие контакты через бота нельзя.
- Проверка email требует платного/лимитированного ключа HIBP.
- Проверка телефона по базам утечек — заглушка; подключайте источник
  самостоятельно и только законным образом.
- Храните `BOT_TOKEN`, `HIBP_API_KEY` и SMTP-пароль в секрете — они в
  `.gitignore` и не должны попадать в репозиторий.
